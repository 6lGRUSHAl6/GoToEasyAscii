# ASCII-генератор - документация

Консольная утилита для преобразования изображений в ASCII-арт с поддержкой цветного вывода, автоопределения фона терминала и многопоточной обработки.

Поддерживаемые форматы: **JPEG**, **PNG**.

---

## Быстрый старт

Запуск без компиляции:

```bash
go run ascii.go [flags] <путь_к_изображению>
```

Или сначала собрать бинарник, а потом запускать его:

```bash
go build -o ascii ascii.go
./ascii [flags] <путь_к_изображению>
```
для windows

```
go build -o ascii.exe ascii.go
```

---

##  Флаги командной строки

| Флаг | Тип | По умолчанию | Описание |
|------|-----|---------------|----------|
| `-color` | `bool` | `false` | Включает цветной вывод с использованием ANSI truecolor escape-последовательностей |
| `-light` | `bool` | `false` | Принудительно использует рампу символов для **светлого** фона терминала |
| `-dark` | `bool` | `false` | Принудительно использует рампу символов для **тёмного** фона терминала |
| `-width` | `int` | `100` | Ширина выходного ASCII-арта в символах (высота вычисляется автоматически с учётом соотношения сторон) |
| `-ramp` | `string` | `auto` | Набор символов: `auto`, `short` (10 символов), `detailed` (70 символов, рампа Пола Бурка) |

>  **Важно:** если указаны сразу `-light` и `-dark`, приоритет отдаётся `-light` (проверяется первым).

> **Параллелизм:** количество воркеров для обработки строк изображения выбирается автоматически как `runtime.NumCPU()` — отдельного флага для этого нет.

## Автоопределение фона через `COLORFGBG`

Если флаги `-light` / `-dark` не заданы явно, программа пытается определить фон терминала по переменной окружения `COLORFGBG` (её устанавливают многие терминалы, например xterm, urxvt):

- если последняя цифра значения — `7` или больше/равна `9`, фон считается **светлым**;
- во всех остальных случаях (в том числе если переменная не задана) используется **тёмный** фон.

---

## Выбор рампы символов: `-ramp`

Доступны два набора символов:

**Короткая рампа (10 символов)** — стабильно работает на любой ширине, особенно на узком выводе:

```
 .:-=+*#%@
```

**Детализированная рампа Пола Бурка (70 символов)** — даёт более плавные градиенты, но **требует достаточной ширины вывода**:

```
 .'`^",:;Il!i><~+_-?][}{1)(|\/tfjrxnuvczXYUJCLQ0OZmwqpdbkhao*#MW&8%B@$
```

### Режимы `-ramp`

| Значение | Поведение |
|----------|-----------|
| `auto` (по умолчанию) | Автоматический выбор: `detailed` при `-width >= 75`, иначе `short` |
| `short` | Всегда использовать короткую рампу, независимо от ширины |
| `detailed` | Всегда использовать детализированную рампу Бурка, независимо от ширины |

> ⚠️ **Частая ошибка:** запуск с маленьким `-width` (например, `50`) и `-ramp detailed` (или без явного `-ramp` при ширине < 75, когда авто-режим уже выбрал `short`, но ожидалась детализация) даёт зашумлённый, "рябой" результат - на символ приходится слишком мало пикселей для плавного градиента детализированной рампы. Если нужен детализированный вывод — **обязательно увеличивайте `-width` до 75+** и/или явно указывайте `-ramp detailed`.

Для тёмного/светлого фона рампа автоматически инвертируется — см. раздел выше про `COLORFGBG` и флаги `-light`/`-dark`.

## Кеширование ANSI-кодов

При включённом `-color` программа кеширует уже собранные ANSI truecolor escape-последовательности по цвету (`map[[3]uint8]string`, потокобезопасно), чтобы не пересобирать одинаковые цветовые коды повторно — полезно, когда в изображении много блоков с одинаковым усреднённым цветом.

## Примеры использования

**1. Базовый вывод** (ч/б, тёмный фон, ширина по умолчанию — 100, авто-рампа → short)

```bash
go run ascii.go photo.jpg
```

**2. Цветной вывод на тёмном фоне**

```bash
go run ascii.go -color photo.jpg
```

**3. Принудительно светлый фон, без цвета**

```bash
go run ascii.go -light photo.png
```

**4. Детализированный цветной вывод — ширина 150+, рампа Бурка**

```bash
go run ascii.go -color -width 180 -ramp detailed photo.jpg
```

**5. Узкий вывод с короткой рампой (явно)**

```bash
go run ascii.go -color -width 50 -ramp short photo.jpg
```

**6. Запуск скомпилированного бинарника**

```bash
go build -o ascii ascii.go
./ascii -color -width 150 -ramp detailed image.jpeg
```

## Советы по производительности

- Обработка строк изображения автоматически распараллеливается по числу ядер CPU (`runtime.NumCPU()`), отдельно настраивать не нужно.
- Цветной режим (`-color`) увеличивает объём вывода за счёт ANSI-кодов; кеш цветов частично компенсирует накладные расходы.
- Подбирайте `-width` под содержимое изображения и режим `-ramp` — от этого сильно зависит визуальное качество результата (см. раздел про `-ramp` выше).

---

## Обработка ошибок

- Если файл не найден или формат не поддерживается — программа выводит сообщение об ошибке и завершает работу.
- Ошибки записи в stdout (например, при перенаправлении вывода в файл) также обрабатываются корректно.
